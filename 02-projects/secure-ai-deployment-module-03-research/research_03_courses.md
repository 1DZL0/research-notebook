Lens: what already exists, so Module 03 can borrow by reference, avoid duplicating, and fill gaps.

- **Contents.** 0 what Module 02 already links; 1 annotated catalogue (1A labs, CTFs and games; 1B courses and training paths; 1C tools and policy engines; 1D talks and showcases; 1E benchmarks and papers; 1F standards and vendor guidance; 1G incident write-ups used as teaching cases; 1H aggregators and items set aside); 2 five "assign these" items; 3 gap analysis; 4 teaching patterns; 5 proposed 60-minute structure and live demo variant; 6 notes for the course author; 7 sources; 8 what I could not verify.

- **The gap** (section 3): almost everything is attack-led, live-LLM and Docker-bound. Nobody lets the learner's own code become the checkpoint, nobody teaches "a string rule is not a boundary" by making you write and then beat one, nobody makes "whose authority" a checkable property, and nobody offers deterministic tool-definition admission control or trace replay as an exercise.
- **Two facts to act on now** (section 6): Excessive Agency is LLM03:2026 (was LLM06:2025); and the repo's terminal lab has a latent prefix-match path check (same class as CVE-2025-53110).
- **Caveat:** the shared search cap ran out before every follow-up was done; about a dozen items are second-hand and flagged.

## 2. Ranked "assign these" list: five external items to do after Module 03

Ranked by fit to Module 03 (tools, excessive agency, confused deputy, MCP tool poisoning), then by friction. All five are free to start; none duplicates a link already in Module 02 Part 5.

Why: the nearest public syllabus match, in one sitting of about two hours. Hints are progressive, solutions are in a file, it runs in Codespaces (60 free hours a month). It is offence-only, which is exactly why Module 03's defence-side exercises complement it.
2. **PortSwigger Web LLM attacks: "Exploiting LLM APIs with excessive agency" plus the AI-powered scanner labs** ("Exploiting AI agents to perform destructive actions", "Exploiting AI agents to trigger secondary vulnerabilities"): https://portswigger.net/web-security/llm-attacks/lab-exploiting-llm-apis-with-excessive-agency ; https://portswigger.net/web-security/llm-attacks/ai-powered-scanner-vulnerabilities . Why: browser-only, minutes each, and the scanner labs make the agent a deputy that holds carlos's credentials and an internal network position, which is the Part 1 lesson in a live system. Caveats: live LLM so results vary; the scanner labs say solutions are "published shortly"; I could not confirm the labs' difficulty levels.

## 5. Proposed 60-minute structure for Module 03 in the course's existing rhythm

Title as in the course shell: "Tools & excessive agency: the agent's own tools as the risk". Spine: OWASP's three root causes of excessive agency (excessive functionality, excessive permissions, excessive autonomy; LLM06:2025, now LLM03:2026) plus two extra questions Module 02 did not ask: whose authority does the call carry (the deputy), and who controls the tool's definition (poisoning). Every Part keeps Module 02's furniture: a divider with "You will do / You will have", red-hat and blue-hat headings, one graded code exercise at most, and a closing "Part N in a sentence" callout.

Fixtures to add to the Koda mock (all deterministic, no model): tools get_customer(id) and run_sql(sql) side by side; send_email, export_customers(path), run_report(name, flags); a requester field (support agent B owns customers 1 to 3) and an owner field on each record; two MCP manifests (crm-connector, notes-helper) with an approved copy and an offered copy; a 20-call approval stream; the saved traces already in the repo.

"In this module" list (hero text, no dashes):
1. How it breaks. Watch the assistant overreach with no attacker at all, then watch a stranger borrow its authority.
2. How you stop it. Take away what the task does not need, bind the rest to the requester, gate the literal action, then write the check yourself.
3. Your turn. Write the permission for two new tools, then run the bypasses that beat real products' rules.
4. The surface keeps widening. Poisoned tool definitions before the call, after the approval and next door: admit or refuse each manifest.
5. The defender's toolbox. Sort the controls by what they change and which root cause they remove, then replay old traces through your stricter rule.
6. Take it to your own agent. Score every tool on what it can do, whose authority it uses and what pins its definition.

"Part N in a sentence" callouts (Module 02 style):
- Part 1: An agent can overreach with no attacker present; an attacker only has to borrow what it already holds.
- Part 2: Take away what the task does not need, bind what remains to the requester, and gate what cannot be undone.
- Part 3: A permission written as a string is a guess about syntax; a permission written on the parsed action is a boundary.
- Part 4: A tool definition is input: pin it, diff it, and re-approve when its authority changes.
- Part 5: The sandbox, the credential and a gate on the literal irreversible action bound the damage; blanket approval prompts and scanners only change the odds and the time to notice.
- Part 6: The deliverable is the table: tool, root cause, whose authority, what pins its definition.

Live demo variant for a conference talk (about 20 minutes, no network, no key): (1) 3 min, the "authority gap" trace: the assistant holds about seven tools, the task needed two. (2) 4 min, the deputy swap: support agent B asks for customer 42; flip the "act as the requester" switch and show the refusal. (3) 5 min, a rug pull on stage: approve a manifest, flip one line of the description, show admit_tool refusing it; ask the room which line changed. (4) 4 min, the approval stream: twenty calls, two dangerous, a show of hands on which to approve; then the same stream under a boundary. (5) 3 min, replay the saved traces under the stricter rule and read the decision diff. (6) 1 min, the assignment slide (section 2). Optional honest-split slide: one live model call with the audience's own key, with the course's rule never to fake a crack.

If time runs short, cut in this order: the Part 5 replay (keep the sort), Part 4 cards 4 and 5 (keep admit_tool), the AWS scope ladder in Part 6. Keep Part 3 whole: the benign-call check is what stops learners from "fixing" a rule by blocking everything.

## 6. Notes for the course author (found while surveying)

1. **Renumbering.** Excessive Agency is LLM06:2025 and LLM03:2026. The OWASP announcement of 1 to 2 Sep 2026 quotes Michael Bargury saying it is "now number three"; Giskard and a CSA Labs research note give the same full ranking (LLM01 Prompt Injection, LLM02 Sensitive Information Disclosure, LLM03 Excessive Agency). Module 02 and the course shell cite 2025 numbering (LLM01:2025). Module 03 should print both, and say which edition each citation comes from.
2. **Two different "confused deputy" bugs.** The MCP specification's confused deputy is an OAuth proxy flaw (static client ID, dynamic client registration, a consent cookie that lets a crafted authorisation request skip consent). The LLM-agent confused deputy is injected text making an agent spend its own authority (NCSC, CSA, DVLA, PortSwigger scanner labs, Secure Code Game level 5). Many articles blur them. Name both on one slide in Part 1, then teach the second and point at the first.
3. **A latent prefix-match bug in the repo's terminal lab.** lab/tools.py checks paths with str(target).startswith(str(root)), where root is the resolved company/shared folder, with no trailing separator. A sibling folder named shared-anything would pass. This is the same bug class as CVE-2025-53110 in Anthropic's Filesystem MCP server (Cymulate "EscapeRoute", fixed in 2025.7.1). It is not exploitable with today's mock data (the secrets folder is named secrets), and the browser lab's in_bounds() is safe because it requires the prefix "shared/" and rejects "..". Either fix it (resolve then compare with is_relative_to) or use it deliberately as the Part 3 "find the bug in the checkpoint" exercise.
4. **Approval gates.** Module 02's toolbox sort files "approval of the literal action" under Boundary. That stands while a human reads each prompt, but Anthropic's sandboxing post says approval fatigue is the reason for OS-level isolation, and InfoQ reports Anthropic saying users approved roughly 93% of prompts. Suggest keeping "approval of the literal irreversible action" as a Boundary and adding "blanket approval prompts" as a Reducer in Module 03.
5. **Module 02 wording to refresh.** The DeepLearning.AI "Red Teaming LLM Applications" course is 1h39m and "free for a limited time during the DeepLearning.AI learning platform beta" (page updated 28 Sep 2026), not a flat free 90 minutes.
6. **Do not re-link in Module 03** (already in Module 02 Part 5): Gandalf, Agent Breaker as a whole, Tensor Trust, the PortSwigger Web LLM topic page, the DeepLearning.AI red-teaming course, AgentDojo, InjecAgent, garak, PyRIT, promptfoo, CaMeL, Rule of Two, The Attacker Moves Second, the Invariant rug-pull and MCPoison. Link instead to the specific labs and posts listed in sections 1 and 2.
7. **Fixtures that already exist.** The repo's traces folder holds 813 recorded runs (579 unsafe, 145 hardened, the rest other labels), each a JSON-lines file of context, tool_call and result events, and python -m lab.agent --replay already exists, so the Part 5 replay is cheap to build.
